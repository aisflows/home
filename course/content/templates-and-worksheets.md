# 10. Шаблоны И Рабочие Листы

Статус: черновик v6 / усилена роль рабочей тетради как действия, а не бюрократии.

Эта глава - рабочая тетрадь курса.

Здесь собраны шаблоны и контрольные вопросы, к которым можно возвращаться по ходу курса.

Сначала кажется: шаблоны - это скучная бюрократия.

На практике шаблон нужен не для красоты документа. Он нужен, если вы не хотите держать в голове одновременно персонажа, камеру, референсы, тайминг, ошибки, финал и ещё мысль "почему я вообще открыл этот сервис".

Шаблон - это не начальник с печатью. Это чек-лист перед взлётом. Самолёт может быть красивым, но лучше всё-таки проверить, есть ли у него крылья.

**Шаблон** - это не обязательный бланк. Это форма вопросов, которая помогает проверить важные вещи до генерации.

🎬 **Мини-пример.** Если в листе управляемого отрезка есть поле "что не допускать", вы заранее пишете, какой риск нельзя допустить в этом конкретном отрезке. Без этого модель может изменить важную часть сцены, а вы потом будете спорить с результатом, который сами не защитили.

📌 **Как пользоваться:** не закрывайте всё идеально. Отвечайте только на то, без чего следующий шаг начнёт гадать. Если всё ясно в голове, можно не делать отдельный документ.

## 10.0. Карта Главы

Эту главу не обязательно читать подряд как обычный урок.

Это набор форм. Открывайте нужный шаблон в тот момент, когда дошли до соответствующего этапа курса.

Если читать все формы залпом, они могут выглядеть тяжело. Это нормально. Рабочая тетрадь не обязана быть романом. Её задача - открываться в нужный момент и спасать от хаоса.

Как читать шаблон:

```text
не "закрыть все поля идеально"
а "ответить на то, без чего следующий шаг начнёт гадать"
```

Если поле непонятно, не давите его силой. Вернитесь к главе, где этот слой объясняется, или напишите рядом простой вопрос. Например: не понимаете "что сохранить" - спросите себя: **что не должно измениться между версиями?** Лицо, логотип, тон, объект, финальный смысл?

🧭 **Маршрут рабочей тетради:**

Маршрут рабочей тетради: замысел, подготовительный пакет проекта, тайминг, управляемый отрезок, референсы, промпты, карточка модели, ошибка, лучший результат, журнал выводов и выбор инструментов.

⏸ **Пауза:** это не теория и не бюрократия. Это место, где вопросы курса превращаются в рабочую ясность: в голове, в чате, на канве или в документе.

Что нельзя делать:
```

```

## 3. Смысловая Правда Сцены

```text
Что точно происходит:
В чём поворот / смысл:
Что нельзя менять:
Что может быть гибким:
Диалог / текст:
Финальный удар:
```

⏸ **Пауза:** первые три шаблона отвечают не на вопрос "как красиво сгенерировать", а на вопрос "что мы вообще делаем". Если это неясно, дальше промпты будут чинить не картинку, а хаос.

## 4. Таблица Точек Тайминга

Это не план количества генераций.

Это монтажная карта: когда зритель что видит и где появляется смысл.

| Точка | Время | Видимое действие | Диалог / текст | Смысл | Заметки |
|---|---|---|---|---|---|
| 1 | 0:00-0:02 |  |  |  |  |
| 2 | 0:02-0:04 |  |  |  |  |
| 3 | 0:04-0:06 |  |  |  |  |

Правило:

Точки тайминга управляют монтажом и смыслом. Они не задают обязательное количество генераций.

🎬 **Мини-пример.** Три строки тайминга могут быть одним видео-фрагментом, если это одно непрерывное действие. А одна строка тайминга может потребовать отдельной генерации, если там точный знак, текст, продукт или сложный финал. Тайминг - это карта, а не кандалы.

## 5. Лист Управляемого Отрезка

```text
Отрезок:
Какие точки тайминга покрывает:
Длительность:
Сцена:
Главный объект / персонаж:
Главное действие:
Камера:
Диалог / текст:
Нужен стартовый кадр:
Нужен финальный кадр:
Нужны отдельные элементы:
Можно ли делать текстовый тест:
Нужные референсы:
Что сохранить:
Что не допускать:
Ожидаемая ошибка:
```

Правило группировки:

Один отрезок может покрывать соседние точки тайминга только если сцена, главное действие, логика камеры и смысл остаются цельными.

⏸ **Пауза:** таблица тайминга режет историю по времени. Лист управляемого отрезка режет работу по производству. Это разные ножи, не путать.

## 5A. Shot Plan / Storyboard Map

Заполняется после сценария/тайминга и после первичного понимания референсов, но до Frame Pack и до видеопромптов.

Это не prompt изображения и не prompt видео. Это карта шотов, по которой потом понятно, какие start/key/final frames нужно сделать.

```text
Id шота:
Какой timing покрывает:
Что зритель видит:
Что меняется в кадре:
Зачем такая камера:
Роль референса:
Звук / реплика / текстовый cue:
Нужен start frame:
Нужен keyframe:
Нужен final frame:
Куда идёт дальше: Frame Pack / Video Segment Pack / монтаж / титр
```

Если этот блок не заполнен, Frame Pack остаётся черновиком: кадры будут красивыми, но не привязанными к production-задаче.

## 6. Чеклист Референсов

Перед заполнением решите, какой это тип опоры:

```text
прикрепляю в модель
держу рядом для себя
использую как стартовый кадр / финальный кадр / отдельный элемент
разбираю как пример движения
```

Иначе слово "референс" быстро превращается в мешок, куда положили всё подряд и забыли, зачем.

```text
Референс персонажа:
Референс объекта / продукта:
Референс локации:
Референсы элементов: персонаж / одежда / машина / продукт / логотип / предметы:
Референс внешнего вида:
Film still / кадр из фильма:
Что берём из кадра: свет / ракурс / крупность / композиция / глубина / расстановка объектов:
Стартовый кадр:
Финальный кадр:
Референс движения:
Что должно остаться одинаковым:
Что может меняться:
Каких референсов не хватает:
```

## 7. Лист Персонажа

Для photoreal/live-action персонажа сначала заполнить и сгенерировать один главный full-body кадр. Лист ракурсов делать только после принятого результата.

```text
Имя персонажа:
Роль:
Лицо:
Волосы:
Одежда:
Тело / силуэт:
Узнаваемые детали:
Photoreal/live-action style to preserve:
Запрещённые слова/маршруты:
- character sheet / turnaround до принятого full-body кадра
- 3D render / CGI / game model
- серый studio background, если нужен живой cinematic кадр
- bodysuit, если нужен реальный techwear/costume
Нужные ракурсы:
- спереди:
- 3/4:
- сбоку:
- со спины / второй полуоборот:
Нейтральный фон:
Что сохранить:
Что не допускать:
```

⏸ **Пауза:** блок референсов защищает то, что модель не должна каждый раз изобретать заново: лицо, объект, локацию, освещение, цвет, старт или финал.

Если персонаж должен повторяться в нескольких кадрах, можно сделать отдельный лист ракурсов.

Простая форма:

```text
Файл или ссылка для личности:
Нужные ракурсы:
- спереди:
- левый профиль:
- правый профиль:
- 3/4:
- лёгкий наклон головы вниз:
- лёгкий наклон корпуса вперёд:
- чистый фронтальный портрет:
- средний план:
Что должно остаться одинаковым:
Что нельзя менять:
Фон:
Свет:
```

Это не нужно для каждого ролика. Для логотипа, капли воды или предметного reveal такой лист может быть лишним. Для человека, который должен не "переехать лицом" между кадрами, это уже полезная страховка.

## 8. Шаблон Промпта Для Изображения

Назначение: один замороженный кадр.

Этот шаблон - рабочий лист. Если нужен готовый prompt для генератора, сначала отдавайте `Prompt to paste` / цельный prompt body, а уже после него статус, проверку и риски.

```text
Зачем нужен кадр:
Главный объект:
Состояние / поза:
Локация:
Композиция:
Крупность / ракурс:
Освещение:
Материалы и детали:
Вид кадра:
Какие референсы сохранить:
Что не допускать:
```

Внешняя форма для генератора:

```text
Выдано: image prompt to paste.

Prompt to paste:
[цельный prompt body: главный объект, состояние, композиция, крупность/ракурс, свет, материалы, фон, photoreal/live-action default или явно выбранный стиль, что сохранить, что не добавлять]

Настройки / входные материалы, если полезно:
[модель, формат, входные референсы и роли]

Заметки / проверка вне промпта:
[что проверить после генерации]

Статус источников:
[known / draft / not proven]
```

Если не хватает обязательного лица, продукта, логотипа, текста, роли референса или финального кадра, ставить `DRAFT PROMPT SKELETON - not ready for generation`, а не выдавать черновик как готовый prompt.

Если prompt может увести к публичному человеку, celebrity-like face, known cast, франшизе, official costume или скопированной сцене, переписать positive prompt в безопасный original-fictional вариант. Использовать конкретные архетипы людей и строку: `original fictional unknown performers, not based on any real actor or public figure, no celebrity likeness, no recognizable movie cast, no specific franchise, no official costume, no copied scene composition`.

Не включать:

- длительность;
- движение камеры;
- видео-движение;
- монтажные команды.

Подсказка для film still:

```text
Кадр / ссылка:
Фильм / сцена:
Что берём:
- свет:
- крупность:
- ракурс:
- композиция:
- глубина / передний-средний-дальний план:
Что НЕ копируем:
```

## 9. Шаблон Промпта Для Видео

Назначение: изменение во времени.

Это тоже рабочий лист. Когда пользователь просит prompt to paste, не возвращайте только поля ниже. Сначала скомпилируйте их в чистый model-facing video prompt.

```text
Управляемый отрезок:
Диапазон тайминга:
Длительность:
Начальное состояние:
Главное действие:
Камера:
Непрерывность освещения:
Реплика, если есть:
Финальное состояние:
Какие референсы сохранить:
Что не допускать:
```

Внешняя форма для генератора:

```text
Выдано: video prompt to paste / controlled segment prompt.

Prompt to paste:
[цельный video prompt body: стартовое состояние, одно главное действие, камера, свет/атмосфера, что сохранить, финальное состояние, constraints]

Negative constraints:
[если сервису удобнее отдельным блоком]

Validation / likely failure:
[не вставлять в prompt body, если это не constraint]

Статус источников:
[known / draft / not proven]
```

Если промпт покрывает несколько строк таймскрипта или storyboard panels, `Prompt to paste` должен содержать shot/time blocks и continuity wording. Если не хватает тайминга, исходных референсов, ролей или стартового/финального кадра, ставить по-человечески: `черновик, не готов к генерации`; английский статус `DRAFT PROMPT SKELETON - not ready for generation` можно оставить только как техническую пометку в скобках, если она нужна агенту.

Для Seedance-like controlled segment карточка сегмента не заменяет prompt. Человек должен понимать сегмент на своём языке, но генератор должен получить отдельный копируемый prompt body.

Объясняющая карточка всегда пишется на языке пользователя. Если пользователь работает на русском, не заполняйте карточку английскими служебными словами вроде `draft prompt skeleton`, `Source timing`, `Generation duration setting`, `Edit target`, `repair addresses`, `reference assets`, `safety tail`. Пишите по-русски: `черновик, не готов к генерации`, `исходный тайминг`, `длительность генерации в интерфейсе`, `цель монтажа / что обрезать`, `внутренние короткие отрезки для ремонта`, `входные референс-материалы`. Английский остаётся в копируемом `Prompt to paste`, если пользователь не попросил иначе.

Перед этой карточкой уже должны существовать предыдущие блоки:

```text
Reference System -> Shot Plan / Storyboard Map -> Frame Pack
```

Видеосегмент не создаёт новую Reference Map и не придумывает start/key/final frames с нуля. Он ссылается на уже принятые визуальные опоры и отвечает за движение, камеру во времени, действие, звук/диалог и монтажную пригодность.

```text
Сегмент:
Статус:
Режим:
Тип сегмента: одношотный / мультишотный.
Почему так:
Тайминг и покрытые строки:
Длительность генерации в интерфейсе:
Цель монтажа / что обрезать:
Внутренние короткие отрезки для ремонта, если сегмент мультишотный:
Что происходит:
Камера:
Стартовый кадр:
Финальный кадр:
Входные референс-материалы / прикрепляемые материалы:
- [точный тип] - [что именно фиксирует]
- [точный тип] - [что именно фиксирует]
Сохранять:
Ограничения для видеопромпта / причина:
Ожидаемый сбой:

Prompt to paste:
[отдельный промпт для копирования в генератор, по умолчанию на английском]
```

В этой форме не писать `refs` без расшифровки. Если это прикрепляемые файлы для генератора, называйте блок `Входные референс-материалы / прикрепляемые материалы` и указывайте точный тип:

```text
- @Image1 = single input reference image: [что это] - [что фиксирует]
- @Image2 = Visual Reference Map / Identity Board: [чего карта] - [что фиксирует]
- @Video1 = movement reference video: [какое движение] - [что фиксирует]
```

Если непонятно, является ли файл одиночным кадром или настоящей `Reference Map`, prompt остаётся draft.

Отдельно проверяйте роль кадра. `Входной референс-материал` фиксирует идентичность, среду, свет, стиль, движение или масштаб. `Стартовый кадр` / `ключевой кадр` задаёт конкретную композицию и состояние сцены. Если человек показывает кадр, от которого хочет начинать сегмент, это не просто референс; это кандидат на стартовый кадр / shot image.

Не пишите `image-to-video`, если нет выбранного стартового кадра. Если есть только прикрепляемые материалы для удержания identity/environment/style, называйте маршрут `multi-reference / reference-guided / draft route` и не утверждайте, что набора материалов достаточно для всего ролика.

Не переносите сюда запреты из промпта референс-изображения. Если запрет нужен только для чистого identity reference, start frame, character sheet, product packshot или Reference Map, держите его в блоке `Ограничения для промпта референс-изображения / причина`. Видеопромпт следует принятому сценарию, камере и сценическому решению; ограничивайте только тот риск, который относится к конкретному видеобиту.

Не пишите `тот же объект` / `same object`, если в этой карточке не назван точный входной референс-материал. Лучше: `the primary subject from the attached identity reference`. Если final-frame control в выбранном режиме не доказан, пишите `финальный кадр: target state / optional / deferred`, а не обещайте управление финалом.

`@Image1`, `@Image2`, `@Video1` в этой форме - это role-lines для человека и сборки. В `Prompt to paste` их можно писать только если выбранный генератор реально видит такие handles. Если пользователь вручную перетаскивает изображения в Dreamina/Seedance-like UI и handles не доказаны, держите mapping снаружи prompt body, а внутри prompt пишите семантически: `the attached primary subject identity reference`, `the attached environment reference`, `the attached movement reference`.

Multi-row / multi-shot prompt не должен быть слишком коротким. Для такого сегмента внутри `Prompt to paste` нужны timed/numbered shot blocks, visible action, camera/framing, continuity locks, audio/edit policy и scope-specific constraints. Компактный prompt допустим только для простого one-shot или выбранного minimal route, и это должно быть явно объяснено.

Формат видео, aspect ratio, качество, resolution, fps и общий output format не пишутся внутри `Prompt to paste`, если человек выбирает их в интерфейсе генератора. Они идут в Settings / checklist над prompt. Внутри prompt остаётся только то, что модель должна изобразить и как двигать сцену.

То же правило для длительности: дробный тайминг в сценарии не означает, что генератор умеет создать клип ровно на 3.5s. В русской карточке разделяйте `исходный тайминг`, `длительность генерации в интерфейсе` и `цель монтажа / что обрезать`. Если источник покрывает 3.5s, а UI даёт только 4s, выбирайте 4s в настройках над промптом, добавляйте спокойный хвост и пишите монтажную пометку: `обрезать до 3.5s в монтаже`. Если это ломает действие, перегруппируйте соседние строки в поддерживаемую длительность.

Если после генерации ломается только один внутренний short, сначала выберите маршрут исправления. `Parent Segment Rewrite` нужен, когда меняется весь сегмент. `Local Replacement Short Package` нужен, когда соседние shorts приняты и заменить надо только один кусок.

```text

Что ремонтируем:
Исходный родительский сегмент:
Принятые соседние отрезки:
Сохранить из родителя:
Менять только:
Входные референс-материалы / роли:
Граничные состояния:
Промпт изображения для замены:
Промпт видео для замены:
Монтажная заметка:
```

Для `Parent Segment Rewrite` перепишите карточку сегмента и segment `Prompt to paste`. Для `Local Replacement Short Package` дайте два отдельных prompt: image / start-frame prompt для нового replacement short и video prompt для оживления этого изображения. Repair prompt должен быть полноценным самостоятельным prompt для выбранного short, а не короткой строкой из родительского сегмента.

## 16. Пакет Музыкальных Промптов

Используйте этот лист, если ролик держится на музыке, ритме, вокале, трейлерных ударах, reveal, логотипе или синхроне с монтажом.

Пакет музыкальных промптов не спорит с сегментами. Он строится из того же принятого сценария / Full Timed Script: музыка переводит сценарий в ритм, энергию, паузы, удары и sync targets; controlled segments переводят тот же сценарий в генерационные визуальные куски.

Если музыка не нужна, не получилась, пользователь принесёт свой трек позже или хочет сразу генерировать видео, работа не останавливается. Сегменты и Seedance-промпты строятся от сценария/таймскрипта. В аудио пишем честно: `без музыки`, `свой трек позже`, `музыка в монтаже` или `музыкальный промпт опционален`.

Перед video prompt отдельно решите, что делает генератор со звуком. Музыкальная подкладка - это не весь звук. Музыка, шумы и речь - разные вещи: `музыка не нужна`, `своя музыка позже`, `нужны только шумы`, `речь добавим в монтаже`, `нужен lipsync`, `модель должна генерировать музыку`. Если своя музыка будет поверх или уже есть music prompt/трек, в копируемом video prompt не просим музыкальную подкладку и при необходимости пишем: `No background music. No generated music. Sound effects only: ...`. Это не запрещает шум воды, ветер, шаги, дыхание, удары, речь или спецэффекты, если они нужны. Точные реплики держим в озвучке / lipsync-маршруте, а не прячем в обычный video prompt.

Музыку уточняйте до копируемых video prompts: при появлении music prompt / своего трека, перед controlled segments и перед финальным `Prompt to paste`. Если непонятно, нужна ли музыка внутри видеогенерации, готовый prompt не выдаём - сначала уточняем или помечаем черновиком.

```text
Проект:
Длительность:
Где музыка начинается:
Где меняется энергия:
Где нужен удар / пауза / reveal / логотип:
Темп:
Жанр / настроение:
Инструменты:
Что нельзя:

ElevenLabs Music v2 prompt:
[prompt body]

Suno prompt:
[prompt body]

Universal Music Prompt:
[prompt body]

Sound Design Notes:
[timecode -> sound event / pause / impact / riser / transition]

Что проверить после генерации:
Совпадает ли музыка с таймингом:
Не спорит ли звук с голосом:
Нужна ли более тихая версия:
```

Короткое правило:

```text
музыка должна обслуживать тайминг и кадр
music prompt и controlled segments должны ссылаться на один сценарный/timing source
отсутствие music prompt не блокирует сегменты и video prompts
video prompt должен явно разделять: нет музыки / своя музыка позже / SFX / речь / музыка генератора
не заставляйте один prompt работать за все сервисы сразу
```
